# Reality-check digest (для человека)

Короткая **визуальная сводка** о том, как swarm движется к **результату по исходному плану**, а не только по числу закрытых beads.

## Когда выдавать

- **Периодичность:** не чаще **чем раз в ~16 минут** между сводками (**wall-clock** от момента предыдущей digest).
- **Как сопоставить с лупом ~3 мин:** надёжный ориентир без часов — **каждый 6-й** полный проход после прошлой сводки (6×3≈18 мин ≥16). Если есть доступ ко времени — выдай digest на **первом** цикле, где с прошлой сводки прошло **≥16 мин** (может выпасть на **5-м** цикле, если луп иногда реже/чаще трёх минут).
- **Обычные тики между digest:** выполняй координацию **без** этой развёрнутой сводки — не дублируй простыню каждые 3 минуты.

## Что сравнивать с планом

Ориентир — **документ(ы) плана этапов**, из которых вырос граф beads (README, `docs/plan*.md`, ADR, Stage N в markdown и т.д.), плюс **PRD** (`MEMORY/WORK/<slug>/PRD.md` — `## Criteria` ISC и `progress: M/N`), плюс **`bv`/ready** для факта узких мест.

- **Обязательно:** стадии / вертикали из плана vs **что уже на `main`** (коммиты, смерженные PR — кратко хэши + смысл) vs **ISC-прогресс в PRD**.
- **Не сводить всё к beads:** beads — тактика; план + PRD ISC — **зачем** и **какой большой кусок scope** закрыт.
- Если явного stage-дока нет: скажи честно «план только из beads / из описания пользователя» и опирайся на заголовки эпиков и `bv --robot-triage`.

## PRD sync (sub-VERIFY pass — обязательно вместе с digest)

Reality-check digest — это **sub-VERIFY pass** Algorithm-фазы по текущему PRD. **Дополнительно** к человеко-сводке (формат ниже):

1. Прочитать `MEMORY/WORK/<slug>/PRD.md` (`## Criteria`, `progress`).
2. Сверить каждый ISC с фактом на `main` (`git log`, `br list --status closed`, capture panes).
3. **Edit PRD `## Verification`** — добавить evidence по новым ISC, прошедшим с прошлого digest (commit hashes, bead BD-IDs, test results, screenshots paths). Пример:

   ```markdown
   ### ISC-3: Hero section renders at 320px breakpoint
   - Закрыто bead BD-42 (commit a3f5c2e)
   - tmux capture-pane W3: визуальная проверка прошла
   ``
4. **НЕ меняй `phase: verify` в frontmatter** — оставь `phase: execute`. Полный VERIFY как фаза — только один раз в LEARN при закрытии swarm (`AlgorithmIntegration.md` → **LEARN: завершение swarm**).
5. В digest для пользователя добавь строку: `PRD <slug>: progress M/N ISC закрыто; добавлено evidence для ISC-X, ISC-Y`.

Без этого шага PRD устаревает, и `progress: M/N` врёт. Подробности — `AlgorithmIntegration.md` → **Reality-check digest = sub-VERIFY pass**.

## Правила качества сводки

- **Честность:** если стадия «15%» — скажи почему (что сделано PoC vs build-out).
- **Конкретика:** реальные sha, реальные BD-ID, не выдуманные метрики.
- **Краткость:** одна сводка — **читаемый экран**, не десять страниц.
- Отправлять **оператору** (чат / voice notify по политике проекта); в Agent Mail класть только если человек просил общий статус в почте роя.
